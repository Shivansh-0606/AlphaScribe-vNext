## 🔒 Milestone 3 freeze (2026-08-03)

**Milestone 3 (Frontend Engineering — `frontend/` → `web/` screen build-out) is closed.** Every screen in the frozen Screen Inventory (SCR-01 through SCR-10 — Auth, Workspace Home, AI Access Setup, Company Research, Comparison, Report View, Research Library, Learning) now has a real, live-verified `web/` implementation. Phases 1–8 are complete.

**Closed out immediately before freezing, per explicit direction:**

- **`/docs` — will not be built.** Checked against the frozen specification (`docs/design/05_Screen_Inventory.md`): zero mentions. `/docs` exists only as a legacy 1:1 parity item (`frontend/src/pages/Docs.jsx`, a static developer-docs page — install/API-reference/troubleshooting content, not a product screen). Not required by the frozen spec, so it stays **Not Started** by decision, not by oversight — see §1.
- **`.claude/launch.json` port mismatch — fixed.** It defaulted to port 3000; the project's actual convention (CLAUDE.md, `scripts/run.py`, the backend's `CORS_ORIGINS`) is 3001. Root-caused to `web/package.json`'s `dev` script (`next dev`, no port flag) — fixed there (`next dev -p 3001`) rather than papering over it in `launch.json` alone, so every caller of `npm run dev` gets the right port, not just this one config. Also corrected the same stale-3000 assumption in `web/lib/config/env.ts`'s `NEXT_PUBLIC_APP_URL` default and a comment in `playwright.config.ts`. Full gate re-run clean after the fix: `typecheck`/`lint`/`format:check` clean, 286 Vitest tests passing across 62 files.

**What this freeze does NOT mean:**

- **Not the same as the "Migrated" parity gate.** Every feature built in Phases 1–8 is marked **In Progress** in the tables below, not Migrated — real and live-verified, but not yet through the deeper end-to-end hardening pass the Governing Decision requires. The Legacy Frontend Removal Plan stays blocked until every row in §1–§5 reads Migrated, independent of this freeze.
- **Not a statement that Learning is feature-complete.** Learning's backend (retrieval, prompting, source generation behind the Phase 8 contract in `web/features/learning/integration/schemas.ts`) was, at freeze time, explicitly deferred to a separate Backend & AI phase, not part of Frontend Engineering's Milestone 3 scope. **Stale as of 2026-09-22:** that backend was built and reported complete on 2026-08-05 (two days after this freeze) — it is not missing. Live re-verification the same day found a real citation-gate defect that kept it from reliably working end-to-end; **fixed as of 2026-09-23, live re-verified clean on the no-context path as of 2026-09-24** (see §6's row and `docs/briefs/hardening_learning.md` §9) — still In Progress: the direct confirmation on the `context_report_id` path was run on 2026-09-24 and **failed 2 of 2** on a new, context-path-specific root cause (`hardening_learning.md` §10, Finding C), not a claim it's unbuilt.

Freezing here means: **no further Milestone 3 phases will be opened.** Any subsequent frontend work (the Migrated-parity hardening pass, revisiting `/docs`, etc.) is new scope, tracked as its own initiative, not a Milestone 3 phase.

none blocking promotion; each root-caused to an exact line/function, and
either already fixed or carried forward as an accepted, documented gap (the
same standard already applied to Comparison's and Research Library's own
promotions above, neither of which required every non-blocking note to be
pre-resolved).**

- **Overview + streaming (Sub-Slice 1):** zero product defects. One minor
  UX finding — a dev-facing `backend/.env` instruction leaking into the
  user-visible trace log on the automatic fact-check-retry path — since
  generalized and fixed project-wide (7 sibling instances across

  committed to main).

  in `_infer_unit()` misclassifying ~6 recurring line items (e.g. "Net
  Income Continuing Operations") as `ratio` instead of `currency` (fixed,
  word-boundary regex, commit `cdc2914`); a failed Overview job showing
  "still running" forever on the Financials tab with no error or retry
  (fixed for this one consumer via a new opt-in `useReportStatus` hook).

  (M16) reliably crashed on a large real 10-K via an uncaught
  `NonRetryableLLMError` from output truncation — a deliberate,
  contract-documented (Document 87 §17.1) design boundary whose real-world
  cost this pass made concrete for the first time. Filing Analysis's
  per-output containment now degrades that one output to

  prompt tuning was applied to both. Document 87's retry-completion
  question for Filing Q&A remains a live open item, tracked separately.

  payload does not reach the same truncation ceiling in a real, substantive
  test — resolving the question the Filings sub-slice left open. Separately,
  period-mode surfaced that Financials' own unit-misclassification fix was
  never retroactively applied to already-acquired data — including the
  exact MSFT dataset that first proved that finding — since closed via a
  one-time backfill script, executed and verified against the live database.
- **AI Insights (Sub-Slice 5):** a real follow-up question genuinely builds
  on prior-report context end to end, confirmed against a real LLM output,
  not just architecturally. The same "failed job shows still running
  forever" defect class as Financials reappeared here too, since that fix
  was scoped to one consumer (`FinancialsSection`) only. **Fixed 2026-09-21,
  commit `4214b905`** — `AIInsightsSection` now adopts `useReportStatus`
  (same mechanism Financials uses) to tell a terminal failed/cancelled job
  apart from one still running, with a new `onGoToOverview` hand-off.
  Reviewed PASS by Frontend Reviewer.
- **Export (Sub-Slice 6):** a related but structurally distinct defect —
  the "Open Report View" hand-off was shown the instant any Overview job
  started, not once it actually completed, leading to a dead end if followed
  early. **Fixed in the same commit (`4214b905`)** — `CompanyResearchScreen`
  now gates the `reportId` it passes to `ExportSection` on `useReportStatus`
  resolving `completed`, rather than on the raw `?job=` id being present.
  The export/download mechanism itself (client-side Markdown via
  `Blob`/anchor) already worked correctly once a report was genuinely
  complete.
